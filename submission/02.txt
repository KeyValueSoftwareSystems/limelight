Rosetta is sheet music for machines.

For each recording we produce one file that says what the song does over time: where the beats and bars fall, where the sections change and which ones repeat, where the voice drops out and the drums take the room, where a build starts and where it lands. The file contains no lighting words at all - no fixtures, no colours, no cues. It describes the music, not what you do about it.

A reader turns that file into an experience. Limelight is our lighting reader: it takes the file plus a description of whatever lights you own, and produces the show. Because the file knows a drop is eight bars away, the show can build toward it rather than discover it late. That is the difference you can see in five seconds, side by side against any reactive product.

The same file drives things that are not lighting. We already have a second reader that produces drone-swarm choreography, and it exists to prove the file is not a lighting format in disguise.

Two more things travel with the file. An artist can declare intent - this section should feel like drowning, these are my colours, this one is a condition and that one is only a preference. A venue can declare its own brief - cap the energy, use our brand colours. The system resolves the two and can tell you, at any instant, who chose what.

One property makes all of it work: a frame is a pure function of the file, your rig and the time. Ask for the same moment twice and you get the same answer, which is what lets a show scrub, recover mid-song, and be tested at all.
