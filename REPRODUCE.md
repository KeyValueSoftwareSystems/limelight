# Reproducing this, from a fresh clone

**Never seen this project?** Open **[docs/anatomy-of-a-song-map.html](docs/anatomy-of-a-song-map.html)**
in any browser, or read the PDF beside it. No Claude Code, no server, no install
— what the file is, what goes in it, how it is built and how it is graded, in
tables. `bash tools/makepdf.sh` regenerates the PDF from that HTML.


Nothing here needs my machine. Three commands get you a scored map; the rest of
this file says what each environment is for and what is deliberately not in git.

```bash
bash tools/setup.sh all            # environments, model repo, stems  (~30 min, once)
bash tools/pipeline.sh levels      # audio -> map -> board            (~5 min)
bash tools/verify.sh               # everything that can say "broken"
```

## What is not in git, and why

| thing | where it lands | why not committed |
|---|---|---|
| audio (`*.wav`, `*.mp3`) | `synth/out/`, `synth/incoming/` | rule 1. `python3 synth/compose.py` writes the ten synthetic songs identically on every machine |
| separated stems | `work/stems/htdemucs_6s/<slug>/` | ~40 MB a song, and `tools/setup.sh stems` regenerates them |
| virtualenvs | `work/{audio,basicpitch,mir}/` | rebuildable, machine-specific |
| ChordMini checkout + checkpoint | `work/chordmini/` | somebody else's MIT repo; the checkpoint is not ours to redistribute |
| MERT vectors (`*.vec.f16`) | `maps/model/` | 2 MB a song of floats, regenerated by `listen/vectors.py` |

`work/` is gitignored in full. Override any of it:

| variable | default | what it does |
|---|---|---|
| `LIMELIGHT_WORK` | `<repo>/work` | root for everything generated |
| `LIMELIGHT_STEMS` | `$LIMELIGHT_WORK/stems/htdemucs_6s` | where the tools look for stems |
| `LIMELIGHT_MAPS` | `maps/model` | which directory the writers read and write |
| `LIMELIGHT_CHORDMINI` | `$LIMELIGHT_WORK/chordmini` | the chord model's checkout |
| `LIMELIGHT_PY_AUDIO` | `$LIMELIGHT_WORK/audio/bin/python` | the heavy env |
| `LIMELIGHT_PY_BASICPITCH` | `$LIMELIGHT_WORK/basicpitch/bin/python` | the 3.11 env |

`LIMELIGHT_MAPS` is the one that matters for etiquette: it is how you build a map
for a song somebody else owns without writing over their file.

```bash
LIMELIGHT_MAPS=maps/<yourname> bash tools/pipeline.sh the-nights
```

## Why three Python environments

They genuinely conflict. This is not tidiness.

| env | holds | why it is separate |
|---|---|---|
| `audio` | torch, librosa, demucs, transformers 4.44, nnAudio | the workhorse; everything below fights it |
| `basicpitch` | basic-pitch (ONNX) | **python 3.11 only** — it pins numpy 1.23, which does not build on 3.12, and pulls its own tensorflow |
| `mir` | beat_this | its torch pin fights `audio`. Downbeat cross-check only. madmom is NOT installed, so no DBN post-processing |

A step whose environment is missing is **skipped with a note**, not failed. With
only the standard library you still get grid, structure, energy, bar phase,
moments, phrases and stereo — a map that validates and scores.

## The order the pipeline runs in, and what depends on what

```
ear.py            grid, beats, chapters, moments, energy, sections     stdlib
  |
separate.py       stems -> accents + per-bar stem levels               audio env
  |
deep.py           mood, novelty, lyrics  (MuQ, Whisper)                audio env
  |
barphase.py       which beat of four begins a bar, from the recording   <-- must precede derive
moments.py        drops and stops moved to the measured loudness step   <-- and this
  |
derive.py         phrases, phrase_grid, structure_check                 stdlib
pump.py           sidechain depth                                       audio env
stereo.py         width and pan, decoded from the RELEASE not synth/out stdlib
stempitch.py      bass notes
chordmini.py      chords                                               audio env + checkpoint
pyin_melody.py    melody, where the voice is confidently pitched       audio env
notes.py          every note on every stem  (basic-pitch)              3.11 env
melody.py         melody as the top voice of those notes, where pyin declined
attack.py         every accent moved to its own measured attack        audio env
vectors.py        per-beat MERT embeddings -> <slug>.vec.f16           audio env
upgrade_map.py    whatever else is derivable from the file itself      stdlib
```

`barphase.py` and `moments.py` must run before `derive.py`, because phrases are
built on the bar line and the moment times. Everything after `separate.py` is
order-independent apart from `notes.py` -> `melody.py`.

## Checking a change

`tools/verify.sh` runs all of it. Individually:

```bash
python3 validate.py maps/model/*.map.json     # well-formed, no lighting words, sorted
node readers/src/apptest.js                    # all rooms + sky + score lanes draw
node readers/src/smooth.js                     # per-frame deltas vs the layout's own limits
python3 listen/metaeval.py levels              # does each check react to ITS OWN field only
python3 listen/mapeval.py levels               # the board
```

Two rules about the numbers, both learned the hard way and both in AGENTS.md:

- **Never grade a thing against its own output.** `ear.py` places chapters AT the
  bar phase it chose, so "the chapters agree with the bar line" is arithmetic, not
  evidence. That mistake hid a wrong bar line on Mizhiyoram for a whole day.
- **A change to the scorer must make a corrupted map score WORSE.** `verify.sh`
  asserts the two deliberately broken maps still read 0.00. If you change
  `listen/mapeval.py` and they do not, the change is wrong however good it looks.

## The board

`python3 listen/mapeval.py <slug>` appends to `synth/learning/mapeval.jsonl` and
that file is what the page at `127.0.0.1:8770/score` reads. Re-run it after
changing a map or the board still shows the old number.

```bash
python3 synth/serve.py                                   # portal on 127.0.0.1:8770
for s in levels starlight mizhiyoram dont-look-down the-nights; do
  python3 listen/mapeval.py "$s"
done
```
