# readers

**The map is the universal thing.** It describes the music and knows nothing about output.
A *reader* takes the map and does something with it in one domain.

Each reader has **its own output format.** There is no single universal "frame" — that word
belongs to the lighting reader only.

| reader | output | status |
|---|---|---|
| `lights/` | a **frame**: brightness, colour, position, 40× a second | **building** |
| `chapters/` | a text list of timestamps — paste into a video description | **building, ~20 lines** |
| editors | cut points on beats and chapter boundaries | not built |
| games | a note chart, density following energy | not built |
| fitness | a pace curve | not built |
| phones | a colour per seating block, 50,000 at once | not built |
| cars, drones, homes | whatever those surfaces do | not built |

## Why two readers before the 18th and not one

One reader makes this a lighting project. Two readers — even when the second one is twenty
lines — make it a format, and the difference is visible on stage in four seconds: *same file*.

Lights are the spectacular one. Chapters is the cheap one that proves the point.
